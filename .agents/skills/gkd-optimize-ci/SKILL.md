# GKD Optimize CI

这是给 `gkd-main` 使用的只读 CI 调查 Skill，面向排队慢、执行慢、重复构建、易失败或 required check 不清晰的项目。它输出可审查的优化方案，不把未知的 workflow 行为补成假设。

## 输入与范围

开始前确认：

- 目标项目根目录、当前 worktree，以及用户要改善的 CI 目标（时延、稳定性、成本或维护性）。
- `.github/workflows/*.yml`/`*.yaml`、复用 workflow、composite action 和相关脚本的读取范围。
- 可用的运行事实：run/job URL 或编号、分支保护/required checks、runner 标签与资源、失败或取消样本。
- 不可改变的发布、审批、权限和兼容性约束。

运行事实优先使用已有的只读查询入口；资料不足时，只询问会改变优化方向的少量事实，其余不确定性列为证据缺口。不得触发、重跑、取消或修改 CI，不直接编辑目标项目工作流，也不提交、推送或发布。

## 结构与事实分析

1. 逐个读取 workflow 的触发器、权限、环境、job、`needs`、条件、矩阵、并发和制品传递；同时追踪复用 workflow 与 action 的实际调用。
2. 画出 job DAG，标记串行等待、可并行分支、聚合 job、失败快停（包括矩阵 `fail-fast`）和条件分支；每条边注明来源文件。
3. 对照可观察的 required checks 和保护规则，确认哪些 job 是合并前硬门槛，哪些只是提示或发布后步骤。看不到设置时明确说明不能判断。
4. 检查依赖、编译和测试缓存的 key、restore 范围、失效频率、跨 job 可复用性，以及缓存过大或互相覆盖的迹象。
5. 查找重复 checkout、依赖安装、编译、测试、制品上传/下载和跨矩阵重复工作；区分真正需要的隔离与可共享结果。
6. 用运行记录核对排队时间、执行时间、失败/取消/重跑、flake、runner 供给和资源瓶颈；没有连续样本时不要推断趋势。

证据必须引用 `path:line`、运行或 job URL/编号、命令摘要和采样时间。每个结论标注“事实”“推断”或“待验证”，并写清证据缺口对建议排序的影响。

## 输出与排序

返回给 `gkd-main` 的报告包含：

1. **目标与基线**：当前瓶颈、测量范围、成功指标和样本限制。
2. **Workflow 与 DAG**：job 依赖、required checks、矩阵/并发和制品路径的事实图。
3. **问题清单**：缓存、重复工作、串行化、fail-fast、runner 或权限配置的问题，逐项附证据。
4. **优先建议**：按 P0（正确性/合并门槛）、P1（时延/稳定性/成本）、P2（维护性）排序；每项说明收益、风险、前置条件、涉及文件/符号、验证和回滚观察点。
5. **实现就绪 PLAN 草案**：若用户需要施工，明确目标行为、最小文件范围、验证命令、授权边界和不能触碰的外部设置。
6. **证据缺口与停止条件**：列出仍需用户提供或只读查询才能确认的少量事实；只对会改变建议排序或实现方案的事实提问，其余不确定性列为证据缺口。

信息完整时形成建议或实现就绪 PLAN；未知结构、required check 或 runner 事实时先询问少量关键事实并报告其余缺口，不猜测。用户确认前停止，并将后续施工交回 `gkd-main` 的 PLAN、执行和审查流程。

## 明确边界

- 本 Skill 只读取 workflow 和运行事实并写建议，不直接修改目标项目。
- 不执行重跑、取消、发布、权限/分支保护变更或其他 CI 写操作。
- 不恢复旧 AIO、状态机、机器合同、固定 head 验收或常驻 watcher。
- 不把固定仓库、绝对路径、runner 名称、凭据或某个平台的默认行为写死在 Skill 中。
