# GKD Legacy Cleanup

这是临时、按需调用的清理 Skill，不进入 `gkd-main` 默认路由，也不提供兼容模式。只有 main 明确给出老项目根目录、清理目标和删除授权时才可使用；本 Skill 完成后可按用户指示删除。

## 边界与授权

- 只在指定老项目根目录内工作，不写入生产 `~/.codex`、其他项目、当前 GKD 仓库自身的活动记录或无关普通业务文件。
- `.gkd/archive/` 中的历史 Markdown 默认保留。历史事实不等于当前活动引用；只有用户明确要求清理历史内容时才列入删除清单。
- 任何删除必须逐项得到 main/用户明确授权。路径归属不明、疑似普通业务、共享文件或无法确认是否为历史事实时停止并报告，不猜测、不静默删除。

## 第一阶段：完整只读盘点

先对目标项目做完整只读清单，不修改文件或 Git。覆盖：

- `.agents/skills/`、`.codex/agents/` 中的旧 GKD Skill、角色和提示词；
- `scripts/`、hooks、配置、CI/workflow、README、AGENTS、docs、templates 中的旧入口和引用；
- 当前 `.gkd/` 活动文件，以及旧状态、合同、队列、日志、receipt、offer、claim、activation、journal、automatic route、fixed-head、watcher、bundle、manifest、lock 等目录或标记；
- 其他文本文件中的旧入口命令、路径、链接和“已执行/成功”描述。

不得只搜索仍然存在的目标路径；已删除路径在文档中的残留同样要记录。

对每项记录路径、引用行、是否可执行、是否为当前活动文件、是否属于历史归档、直接调用方和证据。按以下五类输出：

1. 当前有效规则：仍被当前项目工作流使用，必须保留；
2. 明确旧版 GKD：确认属于旧活动机制，可申请删除；
3. 普通业务：与 GKD 无关，即使命中关键词也保留；
4. 历史事实：归档或变更记录中的事实描述，默认保留；
5. 证据不足：无法确认归属、调用关系或当前/历史性质，停止并交回 main。

盘点完成后先把清单和建议删除项交给 main，未经逐项授权不得删除。

## 第二阶段：按授权清理

收到逐项授权后，仅删除已确认的旧 GKD 文件、目录、Skill、角色、脚本、状态、旧入口，以及当前活动文档中明确指向这些机制的失效命令和链接；同步清理因此变为空的目录和明确失效的文档内容。不要删除普通业务、默认保留的历史归档或用户数据，不新增替代入口。

## 第三阶段：删除后再次扫描

删除完成后，在同一个目标项目根目录再次扫描完整范围：当前 `.gkd/`、`.agents/`、`.codex/`、scripts、hooks、配置、CI、README、AGENTS、docs、templates 和其他文本文件。

- 重点检查已删除文件名、路径、命令、链接，以及把它们写成“已运行/成功/local_ready”的当前活动记录；
- 对历史归档只确认其仍是历史事实，不把它当作当前活动入口；
- 纯策略字符串或说明文字不作为可执行引用，但应在报告中说明保留理由；
- 扫描仍发现已确认旧版文件或当前失效引用时，继续按授权清理或报告阻塞，不宣称完成。

完成后运行 `git diff --check`，报告盘点分类、逐项授权、删除结果、保留项、历史项、证据不足项和删除后扫描结果。除必要的文件存在性和引用检查外，不新增回归测试、平台检查或其他验收流程。

## 报告格式

报告列出：

- 盘点分类和引用行；
- 已授权删除项及实际结果；
- 保留的当前规则、普通业务和历史事实；
- 删除后再次扫描的范围和结果；
- `git diff --check` 结果；
- 未决证据缺口和后续建议。

不得记录生产用户目录中的令牌、账号、机密值或运行时状态。清理 Skill 本身及其文档引用的删除时机留给用户另行授权。
