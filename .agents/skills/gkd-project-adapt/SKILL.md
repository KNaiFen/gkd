# GKD Project Adapt

这是给 `gkd-main` 使用的只读调查 Skill，面向现有工作流不合适、过慢或受本机资源限制的项目。它把项目事实整理成适配建议，帮助 main 修订 PLAN；不把通用默认值当成项目事实。

## 输入与范围

开始前确认以下输入；缺失的材料性信息只提出会改变方案的少量问题：

- 目标项目根目录和当前 Git worktree。
- 用户目标、已批准或待修订的 `.gkd/plan.md`，以及不能改变的行为约束。
- 本机限制，例如操作系统、可用运行时和包管理器、CPU/内存/磁盘、网络或容器限制。
- 已知的 CI、runner、发布渠道和审批约束；没有这些事实时明确记录缺口。

只读取目标项目和允许的协作材料，输出调查结果和建议。不得直接修改目标项目代码、配置、工作流或发布资产；不得提交、推送、触发外部动作，也不得写入目标项目之外的状态副本。

## 调查清单

按证据可得性检查，不假定项目使用某种语言或平台：

1. 识别语言、框架、构建系统、包管理器、workspace/monorepo 边界和生成文件。
2. 找到实际的格式化、静态检查、单元/集成/E2E 测试、构建和本地开发命令；记录入口文件及必要的版本约束。
3. 阅读 CI 配置（包括 Actions workflow、复用 workflow、脚本和 runner 标签）以及本地与 CI 的差异，标出重复步骤和不可复现条件。
4. 调查发布方式、触发条件、制品来源、审批点和回滚事实；看不到凭据或平台设置时只记录不可见，不猜测其内容。
5. 结合本机资源判断瓶颈属于依赖安装、编译、测试、容器、网络、并发还是发布等待，并区分测量事实和推断。
6. 记录与当前目标直接相关的兼容性、迁移成本、失败风险和未验证假设。

证据使用 `path:line`、命令及其摘要、运行链接或用户提供的事实；每条建议都标注证据、置信度和仍需核对的假设。无法读取的文件、私有设置或缺少的运行样本必须列为证据缺口。

## 输出

按以下章节返回给 `gkd-main`：

1. **现状摘要**：项目结构、当前工作流和最影响目标的约束。
2. **证据表**：事实、来源、置信度和未覆盖范围。
3. **适配选项**：按影响/成本/风险排序，说明保留现状、局部调整和较大改造各自的前提。
4. **推荐方案**：给出项目特定的工作流、工具或资源调整；需要施工时写成实现就绪 PLAN 的目标、文件/符号范围、验证和授权边界。
5. **未决问题与停止条件**：只列会改变推荐的少量问题，并说明得到答案前不能确认的部分。

信息完整时直接给出建议或实现就绪 PLAN；信息不足时只询问影响方案的少量问题。用户确认前停止，不开始施工。任何建议都必须回到 `gkd-main` 的 PLAN、用户确认和主代理审查流程。

## 明确边界

- 本 Skill 只调查和写建议，不直接修改目标项目。
- 不恢复旧 AIO、状态机、机器合同、固定 head 验收或常驻 watcher。
- 不把一次项目的绝对路径、仓库名、用户名、runner 名称或凭据写进可复用指令。
- 不能取得的运行事实不以模拟结果替代；应报告证据缺口和对结论的影响。
