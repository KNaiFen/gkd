# GKD Intake

这是给 `gkd-main` 使用的轻量需求问答 Skill。它读取用户请求，以及已经存在时的目标项目 `.gkd/plan.md` 草案；它只整理事实和未决事项，不创建运行时问答接口、JSON schema、状态文件或固定轮数。

## 触发条件

当请求缺少会改变施工决定的事实时使用本 Skill。材料性缺口是会改变以下任一项的未知信息：

- 目标：要解决什么问题，以及结果对谁有用。
- 范围：涉及哪些项目、目录、文件、符号或明确排除项。
- 验收：用什么可观察结果、测试或检查判断完成。
- 行为约束：必须保持或禁止的行为、兼容性、性能和风险边界。
- 工作目录：应在哪个仓库、分支或 Git worktree 中调查和施工。
- 授权：用户是否批准方案、写入、子代理、自动执行，以及提交、推送、合并或发布等外部动作。

措辞、命名、格式等不会改变上述决定的细节不是材料性缺口，由 `gkd-main` 自主判断。

## 提问顺序

按目标、范围、验收、行为约束、工作目录、授权的顺序检查；已有 `.gkd/plan.md` 中明确且未被新请求推翻的事实可复用。每轮只问当前最重要的一个缺口：问题要说明已知上下文、缺少的决定，以及两三个可选方向（必要时允许用户给出其他答案），避免一次罗列问卷。

收到答案后，`gkd-main` 将答案整理回 `.gkd/plan.md` 草案，并保留仍未解决的事项，再按顺序检查下一个缺口。默认值、沉默或含糊回答都不等同于用户批准材料性决定。

## 停止边界

- 目标、范围、验收、行为约束、工作目录和授权均已足够时，直接返回“无需问答”，交给 `gkd-main` 继续形成或修订 PLAN。
- 用户拒答、答案互相矛盾，或回答仍不足以判断影响时，报告具体未决事项和冲突点给 `gkd-main`，不要擅自选择、扩大范围或开始施工。
- 本 Skill 不替用户确认材料性方案，不启动执行或验收角色，不修改目标项目代码，也不把问答过程保存为机器状态。
